Spotify Deck

Designing a KDE Plasma desktop media widget with a local-first security boundary.

KDE Plasma 6QMLDBusMPRISSecurity design

Overview

Spotify Deck is documented as a translucent KDE Plasma desktop widget for current-track information, playback controls, volume adjustments, and media status. The repository currently includes design, architecture, and security documentation; the implementation described in those documents is not yet present in the published repository.

Architecture & approach

The documented architecture reads media state through KDE's local MPRIS model. The intended interface presents state through QML and sends playback controls back to the active desktop media player over DBus, rather than using Spotify's Web API.

Engineering takeaways

  • Compared local desktop IPC against cloud-based API integration.
  • Documented the relationship between package metadata, applet state, and the visual UI.
  • Recorded tradeoffs around credentials, command execution, and untrusted track metadata.
  • Separated a design specification from evidence of deployed code.

Security perspective

The intended design avoids OAuth tokens and does not require the widget to store Spotify credentials. Its documentation specifies a static application-launch command rather than shell commands constructed from media metadata. These are documented design choices, not an independent audit of a working release.

Next improvements

Publish the widget source, test installation on KDE Plasma, add screenshots, and verify threat-model assumptions against actual code.
