Linux Home Lab

I built a Linux home lab to get hands-on experience with the systems that applications and networks run on. I use it for virtualization, containers, remote administration, and testing software outside my main desktop environment.

DebianUbuntu ServerKVM/libvirtDockerSSHTailscale

What I run

My setup starts with a Debian Linux workstation. I use KVM/libvirt to run virtual machines, including Ubuntu Server, and Docker for self-hosted software. SSH, Bash, and Tailscale are part of how I work with and manage the environment.

Host system
Debian Linux

Daily Linux environment, command-line tools, package management, and system troubleshooting.

Virtualization
KVM / libvirt and Ubuntu Server

Separate server workloads from the host and practice running and administering a Linux guest.

Applications
Docker and self-hosted services

Work with containerized applications and local services. I also use Ollama with Open WebUI as a local AI setup.

Access and tools
SSH, Tailscale, Bash

Remote command-line access, private device connectivity, and day-to-day Linux administration.

What this teaches me

I'm using the lab to understand infrastructure beyond writing application code. The technologies overlap with tasks that systems, cloud, and security teams handle, even though this is a smaller personal environment.

  • Virtualization: How a host and guest operating system are separated and how server workloads can be isolated.
  • Containers: How to run applications with their own dependencies and manage them separately from the underlying OS.
  • Remote administration: How SSH and a private overlay network fit into access to machines and services.
  • Operations: How to investigate service failures, check system state, and make configuration changes from the terminal.

What I want to add

These are next steps, not deployed features. I want to move toward a more structured lab with better network boundaries and documentation.

  • Network isolation: A dedicated router or firewall and separated lab devices or subnets.
  • DNS services: Pi-hole or a similar resolver/filtering service on the private network.
  • Identity and access: A small authentication lab to study account management and least privilege.
  • Visibility: Centralized logs, basic monitoring, and a repeatable way to check service health.

Documentation

I'm working toward a sanitized network diagram, a service inventory, setup notes, and troubleshooting examples. I won't publish real credentials, private keys, or details that could expose my home network.
